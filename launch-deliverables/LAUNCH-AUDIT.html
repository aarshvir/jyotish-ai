05Kundali accuracy methodology — your "no 1% mismatch" bar

Accuracy is engineered in two layers so the output is computed, not guessed, and grounded in classical sources rather than the open internet.

1 · Deterministic astronomy

All positions come from the Swiss Ephemeris (sidereal, Lahiri ayanamsa, whole-sign houses) via your Python service — the same engine behind the live forecast. Divisional charts (D9/D7/D10) and the Vimshottari dasha timeline are pure functions of those longitudes, unit-tested against known anchors (Aries 0°→Aries Navamsa, Taurus 0°→Capricorn, Gemini 0°→Libra).

2 · Scripture-grounded interpretation

Narrative is generated from the computed facts and grounded in Brihat Parashara Hora Shastra via your RAG index — not scraped web text. If the model is unavailable, deterministic fact-specific fallbacks fire, so a paying user never sees an empty or generic section.

Required before charging: run the QA harness on 2–3 charts whose readings you already trust (your own + one or two reference births). Verify the lagna, Moon nakshatra, current dasha, Manglik and Sade-Sati flags match a trusted source (e.g. AstroSage / Jagannatha Hora). The math is deterministic, so once these match, every chart matches — that is your "1% mismatch" sign-off. Note: Sade Sati needs the live Saturn transit; the compute route fetches it best-effort and degrades gracefully if the ephemeris is briefly unreachable.

06Build verification — important caveat

The authoritative npm run build must be run on your machine. The cloud sandbox mounts your Windows project folder over a network layer that intermittently truncates file reads, so its tsc/build output here is unreliable (it reported false syntax errors in files that are actually intact). The writes themselves are correct on disk. Treat a clean local build as the launch gate — it is Step 1 of the launch script below.

Engine unit tests (17) passed in-sandbox while I/O was healthy. Integration imports/types were verified by direct file inspection.
