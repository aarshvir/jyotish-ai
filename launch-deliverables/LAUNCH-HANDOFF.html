3Push to GitHub (2 minutes, on your machine)

Why on your machine, not from the cloud session: the cloud sandbox mounts your Windows folder over a network layer that intermittently truncates reads and can't safely write to .git. All the code is written correctly to disk; the commit/push just needs to run where git and your GitHub login already work. This also keeps your credentials on your machine.
1

Open PowerShell in this folder

Then run: powershell -ExecutionPolicy Bypass -File launch-vedichour.ps1

2

The script gates on a clean build

It runs npm run build first and refuses to commit if the build fails — so you never push something broken. (This is also the real type-check the cloud sandbox couldn't run reliably.)

3

It creates a backup tag, then asks before pushing

A prelaunch-backup-<timestamp> tag is set as your restore point. You type YES to commit + push to origin/main. If Vercel is connected, it auto-deploys.

4Rollback — go back to the original anytime

Two ways, both fast:

Code rollback: powershell -ExecutionPolicy Bypass -File rollback-vedichour.ps1 — resets to the backup tag and force-pushes. (Pass a specific tag as an argument if you want an older one.)

Live-site rollback (fastest, no rebuild): Vercel → Deployments → pick the last good deployment → "…" → Instant Rollback. The site reverts in seconds while you sort out the code at your own pace. Nothing here is permanent.
